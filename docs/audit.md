# Critical audit

The assignment asks for structured extraction from messy change-order PDFs or text, validated JSON with confidence scores, and a short approach/failure-mode writeup with a repository link. It specifies no schema, model provider, web interface, sample corpus or line-item requirement. This implementation chooses a small CLI and Python API. The separate spoken-English recording is a personal submission item and is not generated by this repository.

The initial implementation met the shape of the brief, but its extraction coverage and several validation details needed improvement. The audit reproduced the following defects before adding fixes and regression cases.

| Finding | Resolution | Regression evidence |
| --- | --- | --- |
| Same-line fields were consumed as one value | Split recognized label boundaries without altering evidence text | Inline text and two-column PDF cases |
| Stacked financial summaries and ordinary prose were missed | Add bounded contextual phrases and stacked/pipe label handling, with lower confidence | Form, pipe-table and narrative cases |
| A grounded model amount could lose its credit sign | Check immediate source direction and parentheses before resolving money | Credits with model raw values omitting signs/currency |
| A model could relabel an original total or assert negated/signature-only approval | Reject explicit semantic contradictions | Total substitution, approval negation and signature cases |
| The output model accepted impossible ISO-shaped dates | Validate actual calendar dates as well as shape | February 30 rejection |
| Low-confidence optional values could bypass review | Apply the threshold to every resolved field | Model-derived optional status case |
| Repeated identical quotes pointed to the first occurrence | Preserve occurrence-specific local extraction offsets | Repeated amount quote case |
| Field states and span metadata were incompletely constrained | Reject duplicate conflict alternatives, inconsistent review flags and out-of-page spans | Public-model invariant cases |
| Decimal arithmetic had no explicit magnitude budget | Bound amounts to 18 integer digits and check exact cents at that boundary | Large-amount arithmetic case |
| Provider response size was checked after full buffering | Bound the streamed response and test size/timeout failures | Provider transport cases |
| The original corpus was narrow; p95 indexing understated small-sample tails | Expand fixtures, separate recall/precision/abstention, use nearest-rank p95 | Evaluation and benchmark scripts |

The current corpus contains 14 synthetic documents with 128 known-value assertions and five expected unresolved fields. It includes mixed case, wrapped text, credits, zero values, inline and pipe fields, stacked form wording, prose, missing currency, conflicts, bad dates, arithmetic errors, and a two-column/two-page PDF. Real OCR is exercised separately in the test suite.

The corpus was used during development; passing it is regression evidence, not a held-out accuracy result. No API credential was available for live provider testing. The request/response path, grounding, semantic checks, refusal, truncation, timeout and size limits are tested with mocks, and that limitation is stated in the submission writeup.

Remaining practical limits are arbitrary PDF layouts, handwriting, pre-existing OCR errors, model semantic errors beyond the explicit checks, multiple orders in one input and uncalibrated confidence. None can be honestly removed by adding more synthetic examples. Real employer documents and held-out annotation are needed to measure those limits. The implementation reports review requirements and preserves evidence instead of claiming universal extraction.
